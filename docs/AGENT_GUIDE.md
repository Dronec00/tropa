# Гайд для агента: как работать с «Тропой»

## Что это за проект

Процедурный лес на Godot 4.7: мир строится кодом из `scripts/main.gd`,
никаких тяжёлых сцен и ручной расстановки. Всё, что видно, генерируется:
рельеф, деревья, трава, вода, избы, костёр.

## Порядок работы

1. Прочитать `TODO.md` — там статус и приоритеты (P0–P3).
2. Взять один пункт, проверить, что он не отмечен `[x]`.
3. Найти код: `grep` по ключевым словам, `read` файл целиком, если он небольшой.
4. Сделать изменение **точечно** (edit, не перезапись файла).
5. Проверить:
   - `godot --headless --path . res://scenes/main.tscn --quit-after 20` — нет ошибок;
   - если менял визуал — скриншот или замер FPS;
   - если менял производительность — цифры до/после.
6. Отметить пункт в `TODO.md`.
7. `git add -A && git commit && git push`.

## Как делать скриншоты (macOS)

```bash
pkill -9 -x Godot; sleep 2
(TROPA_TOD=day timeout 24 godot --path . res://scenes/main.tscn --resolution 1600x900 -- --at 8,-8 > /tmp/shot.log 2>&1 &)
sleep 13
WID=$(/tmp/wlist | grep '"Width": 800' | cut -f1 | sort -n | tail -1)
screencapture -x -o -l"$WID" /tmp/shot.png
pkill -9 -x Godot
```

`--at X,Z` — телепорт игрока. `TROPA_TOD` — время суток.

## Как мерить производительность

```bash
TROPA_FPS=1 godot --path . res://scenes/main.tscn --resolution 1600x900 --disable-vsync
```

В логе появятся строки `[perf] fps=…`. Считать среднее по последним 6 значениям.
Сравнивать только одинаковые условия: разрешение, время суток, точка спавна.

## Типичные грабли этого проекта

- `:=` не выводит тип из `Variant` — писать `var x: float = …`.
- `pkill -f "Godot"` может убить сам себя: использовать `pkill -9 -x Godot`.
- Godot берёт не ту сцену, если запускать из папки проекта без явного пути.
- `FogVolume` в Godot 4 — `extents` + `RenderingServer.FOG_VOLUME_SHAPE_BOX`,
  а не `size`/`SHAPE_BOX`.
- Шейдерные юниформы с `/` (например `glow_levels/3`) задаются через `env.set(...)`.
- Листва обязана быть alpha-cutout, иначе деревья становятся прозрачными.
- Туманные объёмы дорогие: отсекать по дистанции, иначе минус 30 fps.
- Прозрачные диски (лужи, зола) легко превращаются в «кляксы» — делать мягкую кромку.

## Работа рядом с другим агентом

В проекте может работать второй агент (например, делает персонажа в своих файлах).
Правила, чтобы не утопить его работу:

1. **Смотреть `git status --porcelain` перед каждым коммитом.**
2. **Стейджить только свои файлы** — `git add путь1 путь2`, никогда `-A`.
3. Чужие изменения не откатывать, не форматировать, не «улучшать».
4. Если чужой файл нужен для проверки — читать, но не менять.
5. Разные ветки — лучший вариант: `git switch -c character`.
6. При `rejected` — `git pull --rebase`, без `--force`.

Пример безопасного коммита:

```bash
git status --porcelain
git add scripts/main.gd TODO.md docs/night.png
git commit -m "Короткая суть

- пункт
- пункт"
git push
```

## Стиль кода

- Одна функция — одна задача, не длиннее ~80 строк.
- Никаких «умных» обобщений: три похожих блока лучше одного запутанного.
- Комментарии по-русски, коротко, по делу.
- Магические числа — в константы с именем.

## Что проверять глазами (а не только кодом)

- Свет: утро/день/вечер — видно ли лес, нет ли «молочной каши».
- Трава: не лезет ли в камеру, нет ли пустых полей.
- Вода: нет ли прямой линии на кромке и тупых концов у ручьёв.
- Костёр: нет ли чёрных кругов и оранжевых блинов.
- Деревья: не растут ли на тропе, не белеют ли дубы.
